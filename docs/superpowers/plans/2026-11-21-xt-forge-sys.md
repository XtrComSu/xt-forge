# XT-Forge-SYS implementation plan

**Goal**  
Ship a native, cross-format systems analysis component in XT-Forge v0.4.7 and document measured coverage.

- [x] Implement native image overview for Mach-O slices, PE executables, ELF executables, and Mach-O members of IPA archives. Verify recorded addresses and archive limits on synthetic inputs.
- [x] Implement file-backed address translation and metadata-backed function indexing for ELF, PE, Mach-O, and IPA. Verify on compiled x86-64 and arm64 fixtures, including stripped inputs.
- [x] Add in-process x86 and arm64 disassembly, bounded direct control-flow recovery, and local PC-relative references. Verify the launcher and both MCP surfaces on compiled fixtures.
- [x] Index direct calls and PC-relative data references across functions. Recover plausible direct-call destinations without metadata and distinguish jumps to known entries as tail-jump candidates.
- [x] Expand function recovery beyond direct-call destinations. Resolve indirect dispatch, switch tables, and tail calls where the recovered semantics support them. Recovered x86-64 offset tables and both arm64 forms (byte table scaled by the instruction stride, and signed-word table) on ELF, PE, Mach-O, and arm64 IPA; every recovered target was checked against the reference disassembly's instruction boundaries.
- [x] Lift common x86 and arm64 instructions to typed native IR and render register-level pseudocode. Verify preserved branch, call, arithmetic and stack effects on compiled fixtures.
- [x] Recover ABI-aware integer arguments, stack data flow, returns, and structured C for supported acyclic leaf functions. Recompile and compare results on optimized and unoptimized cross-format fixtures.
- [x] Compose structured direct calls and tail transfers between independently verified same-image functions. Reuse per-request analysis, track ABI clobbers, and compare emitted C across all four input formats.
- [x] Summarise loops. A function whose loop has a single-block body and one exit test is now emitted as imperative C: a declaration per value the loop changes, a `for (;;)`, and the exit test as a `break` where the compiler put it. Verified by running the recovered function against the original for 4096 inputs, alongside the 16 acyclic functions the fixture already covered. Recovered loops are recognised by a cycle check on the block graph (a back edge whose target can reach its source again), so a forward `jmp` is no longer miscounted as a loop.
- [ ] Extend structured recovery to recursion and richer types, expand the corpus, and compare function boundaries, control flow, and pseudocode against IDA reference results. **Blocked on reference tooling**: this machine has no IDA (`re ida status` reports `idalib`, `idat64`, `idat`, `ida64` all null and the HTTP bridge unreachable) and no Ghidra headless, so the IDA comparison cannot be run here. Recursion is diagnosed rather than mistaken for a loop (a call edge is not control flow, so a self-call no longer looks like a back edge) but it still returns no summary: a recursive callee has no closed form to compose. Multi-block bodies, multiple loops, unsupported calls, and mixed-width incoming arguments can decline with a reason. Supported same-image calls before and inside a single-block loop are recovered. `structured_declined` carries that reason through the CLI and both MCP surfaces, so an unsupported function is distinguishable from an analysis that never ran.
- [x] Expose the analysis through CLI and MCP, preserve project annotations, and measure cold and warm latency, result size, and agent round trips. `re dispatch-native` and `re_dispatch_native` join the existing verbs on both MCP surfaces; analyst renames and comments from the overlay database are merged into every SYS result and accepted as `--target` names. Measured on a 12-case ELF: functions 9 ms / 3.1 KB, decompile 4 ms / 3.6 KB, dispatch 3 ms / 0.7 KB, whole-binary cross-references 4 ms on the fixture and 32 ms on `/bin/ls`, and 195 ms for the function index of a 315 MB binary. Three agent round trips over MCP cost 639 ms and 19.8 KB of responses; the Python launcher adds about 160 ms of interpreter start-up per call.
- [x] Document SYS and ship an RE repository template with a reproducible report, walkthrough, and real commit activity.
- [x] Verify the release packages and cross-platform coverage before assigning v0.4.7 release status. `VERSION`, `pyproject.toml`, and `package.json` all report 0.4.7; `CHANGELOG.md` records the release; the Python wheel (`xt_forge-0.4.7-py3-none-any.whl`) and npm package (`xt-forge-0.4.7.tgz`, 253 files) both build; a cold `install.sh` with isolated `CARGO_HOME`/`GOPATH` exits 0 and reports 0.4.7; the shipped-package contract tests and the full 524-test Python suite pass. Cross-platform coverage is the four formats verified end to end through the real launcher and both MCP surfaces (x86-64 ELF, PE, Mach-O, and arm64 Mach-O inside an IPA).

## Known limitations

- Structured recovery supports linear multi-block loops, top-tested loops, and conditional bodies with a supported common join. Compiler-generated conditional loop fixtures at `-O0` have been checked on ELF, PE, x86-64 Mach-O, and arm64 Mach-O. More than one loop, unsupported calls, recursion, and more complex control-flow shapes can decline with a reason in `structured_declined`. A mixed-width arm64 loop has also been checked against a host-executed reference. Aggressive optimisation regularly leaves that shape: the fixture compiled at `-O2` peels its loop into a guarded fast path plus a two-stride body, which declines. Dispatch recovery is unaffected and works on all of these.
- Dispatch recovery recognises the table idioms GCC and Clang emit for dense switches. Compilers avoid tables entirely for small switches (an 8-case arm64 `-O2` switch becomes a compare/`csel` chain), and sparse or range-split switches can produce several tables per function, of which only the one feeding the indirect branch found is reported.
