## 2. Where the work actually landed

### 2.1 Indirect dispatch recovery — closed

`native/xtforge-go/internal/sysimage/dispatch.go` (602 lines, new).
`RecoverDispatch` → `findJumpTables` → `recoverJumpTable`, three table kinds:
`x86_offset_table`, `arm64_byte_table`, `arm64_offset_table`.

Targets are kept in **index order** — no sort, no dedupe. This is deliberate:
`case 0` must be `targets[0]` or every recovered switch is silently off by one.

Exposed as `re dispatch-native` and `re_dispatch_native` on both MCP surfaces.

### 2.2 Structured loop recovery — closed, but narrower than it sounds

`native/xtforge-go/internal/sysimage/structured_loops.go` (701 lines, new).

Before this, `summaryNode` was a pure expression tree, so a loop had no
representation at all and any function containing one declined. Now:

- Loops are found by **a cycle check on the block graph**: a back edge is an edge
  whose target was numbered no later than its source *and* which can reach its
  source again. The second half matters — an early version counted the forward
  `jmp` in `sum_to` as a back edge and reported two loops.
- Values the loop writes (`loopCarried`) become declared `vN` locals, excluding
  stack pointer, `flags`, `xzr`, `x30`.
- A value in an argument register is only a parameter if it *still* holds the
  argument at loop entry (`initial.text == "argN"`). Otherwise it is a `vN`.
  This is why compilers reusing argument registers as scratch do not produce
  fake parameters.
- The exit test is emitted as a `break` **where the compiler put it**, not
  rotated into a `while (cond)` head. Rotation would require proving the trip
  count is preserved; emitting in place is faithful for free.
- `emitBody` returns the condition under which the loop **continues**; the
  renderer negates once via `if (!(X)) break;`. Getting this backwards produced
  `!!(x)` double negation, and a flags-rewrite bug produced `arg0 != 0x1` (the
  pre-decrement value) instead of `arg0 != 0x0`.

Verified output (`/tmp/syswork/lp2`, x86-64 `-O1`):

```c
uint32_t count_down(uint32_t arg0) {
    if (arg0 == 0x0) {
        return arg0;
    }
    uint32_t v0 = 0x0u;
    for (;;) {
        v0 = (v0 + arg0);
        arg0 = (arg0 - 0x1u);
        if (!(arg0 != 0x0)) break;
    }
    return v0;
}
```

### 2.3 Recursion no longer mistaken for a loop — closed

A real bug found while probing recursion, not a feature. `recoverFlow` records a
`call` edge for every direct call **including a call back to the block being
analysed**, so a self-recursive function looked like a loop and was sent down the
loop path, declining with a loop-specific reason. Call edges are now excluded
from both `findLoops`/`numberBlocks` (`structured_loops.go`) and `reachesCycle`
(`structured.go`).

Recursive functions still return no summary — a recursive callee has no closed
form to compose — but they are now declined as an uncomposable call, not as an
unsummarisable loop. The distinction matters when reading the reason string.

Test: `TestStructuredTreatsRecursionAsAcyclic` in `structured_test.go`.

### 5.2 Loop recovery works in a narrow window — I measured it

This is the sharpest limitation and the easiest thing to overstate in a demo.
Measured on the same `loop_sum` function:

| target | `-O0` | `-O1` | `-O2` |
|---|---|---|---|
| x86-64 ELF | declined: body spans 2 blocks | **recovers** | declined: path into loop branches without a usable condition |
| arm64 Mach-O | declined: body spans 2 blocks | declined: `opaque` on `madd` — loop closed to `madd`/`umull` | declined: `opaque` on `madd`, same straight-line shape as `-O1` |

So: **x86-64 at `-O1` is the one shape that works today.** At `-O0` both
architectures produce multi-block bodies (which the summariser requires to be a
single block). At `-O1` on arm64, LLVM strength-reduces the loop away entirely
into straight-line `madd`/`umull`/`csel` — there is nothing left to recover, and
the decline is `unsupported operation "opaque"` on the `madd`.
At `-O2` on x86-64 the loop is peeled into a guarded fast path plus a two-stride
body.

**Consequence for `scripts/verify_sys_native.py`:** the shared `-O2` fixtures
cannot exercise loop recovery, and neither can arm64. That is why `verify_loops`
compiles its own dedicated x86-64 `-O1` fixture instead of reusing the fixture
family. Do not "simplify" it back into the fixtures — it will go green while
testing nothing.

Declines are never silent: `structured_declined` carries a reason through the CLI
and both MCP surfaces, so an unsupported function is always distinguishable from
an analysis that never ran.

## 9. Map of the SYS component

`native/xtforge-go/internal/sysimage/` — the native systems-analysis engine.

```
overview.go      image-level facts
functions.go     function discovery / index
disasm.go        recoverFlow — instructions → blocks + edges
lift.go          typed Operation IR; Decompilation carries Name/NameSource
lift_x86.go / lift_aarch64.go   per-arch lifting
dispatch.go      jump-table / switch recovery
xrefs.go         cross-references
elf_unwind.go    unwind tables
structured.go           ABI-aware compilable C; analyzeStructuredWithReason returns a decline reason
structured_state.go     register/slot symbolic state, width aliases
structured_conditions.go condition rendering
structured_loops.go     natural loops → imperative C  (new this session)
```

Pipeline: `Overview` → `Functions` → `Disassemble`/`recoverFlow` →
`liftDisassembly` → `analyzeStructured[WithReason]` → `newCalleeResolver`.

Python side: `xtforge/core/re/sysimage.py` (annotations),
`scripts/verify_sys_native.py` (end-to-end gate).
